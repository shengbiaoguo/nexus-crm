## 按问题记录

| 问题 | 本轮决定及最小落点 | 实现验收要求 |
|---|---|---|
| DC-001 | 当前客户为销售授权根，商机 owner/createdBy 不保留独立授权；按角色成对计算动作/scope；交付/财务字段投影；嵌套 ID 全链校验；业务授权需 role:grant_business，禁止自授及模板提权；每请求查权威库 | 移交/撤权、父子错配、多角色 scope、Token 撤销、跨部门投影、管理员提权拒绝；写入与撤销并发按共同顺序 |
| DC-008 | scope=user:不可变用户ID；操作/目标/参数进入 v1 指纹；同键跨操作冲突；并发最多等 2 秒；失败不缓存；成功至少保留 7 天；过期清理后不保证识别旧 Key | 同 Key 并发、跨操作/目标冲突、响应丢失、COMMIT 未知、授权撤销后重放、过期及清理；真实 MySQL |
| DC-009 | 关键尝试先独立持久化 STARTED，成功随业务写 SUCCEEDED；回滚后独立 FAILED；进程中断保留 UNKNOWN，核对不得伪造驳回 | 预写失败不执行业务；失败写异常返回 503；崩溃有持久线索；核对不覆盖真实成功 |
| DC-011 | ADR-001 引用改为 BR-005、BR-008、需求 §4、INV-004/005 | 引用能追踪到本地真实规则；无新增 BR |
| DC-012 | M1 共同入口；M2 前置申请表和真实阻断查询；M3 所有改变阻断条件的写操作接入同一入口 | 禁止固定 false/缺表吞错；重跑申请创建 vs 启动/结项、取消 vs 启动、范围/验收变化 vs 结项 |

DC-001 的交付经理预分配端点用于解决“项目尚未创建，如何校验 ASSIGNED_PROJECT”的授权起点，不代表关闭 DC-004 的任务/验收建模。scope、部门树、财务登记人与确认人分离等均标为 V1 技术基线，未冒充已确认业务 BR。

DC-009 新增一个轻量尝试表是为保留进程中断前的证据；普通技术日志仍尽力而为，不新增外部队列，也不承诺准确记录任意崩溃点的最终失败原因。审计保存期限仍待确认。
