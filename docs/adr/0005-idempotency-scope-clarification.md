# ADR-005：V1 幂等作用域与失败、过期契约

- 状态：Accepted（设计基线，待实现验证）；Supersedes ADR-002
- 日期：2026-10-29
- 原因：DC-008；保留 ADR-002 的历史理由，消除其“操作参与作用域”与“同键不同操作冲突”的矛盾。
- 关联：INV-006；API §1.4、§3.1；数据模型 §5.1

## 保留的决策

关键命令使用 MySQL 唯一约束，业务事实、成功审计和最终幂等结果同事务提交；Redis 不作为权威；禁止仅靠前端或订单状态代替结果重放。沿用 ADR-002 的取舍，以下规则替换其作用域及处理细节。

## 唯一性与指纹

V1 单企业，scope 固定为 `user:<不可变 users.id>`，`UNIQUE(scope,key)`；Key 为规范化小写 UUID。同一用户的 Key 跨会话、跨命令唯一，操作和目标不进入 scope；不同用户的同一 Key 相互独立，但仍受业务唯一约束。

请求指纹为 SHA-256：API 主版本、稳定业务 operationId、所有规范化路径/目标 ID、通过 DTO 校验后的规范化请求体。规范化使用固定字段顺序和 UTF-8，金额按 CNY 两位小数字符串、ID 按十进制字符串、时间按 UTC；对象键排序，数组保留语义顺序，明确区分 null/缺失，默认值先展开。不包含 Token、requestId、Key；expectedVersion 属于语义内容。算法固定并保存 fingerprint_version=1，升级不得在保留窗口内破坏旧指纹比较。

同主体同 Key 在保留期内更换操作、目标或参数一律 `409 IDEMPOTENCY_KEY_REUSED`。同指纹重试先通过当前认证、动作和对象范围检查再回放；不因已结束业务状态或旧 expectedVersion 拒绝有效重放。权限已撤销返回 403/404，不泄漏旧结果。

## 并发、失败与响应丢失

1. 先完成认证/DTO/当前授权，事务内争用唯一键；禁止在独立事务预提交 PROCESSING。
2. 所有者在同一事务完成状态重检、业务写入、成功审计、最终结果；唯一键冲突的请求等待最多 2 秒，超时返回 `409 IDEMPOTENCY_IN_PROGRESS`、`Retry-After: 1`。等待上限由实现集成测试验证，不能把锁等待超时伪造成业务成功。
3. 提交完成后同指纹回放首次 HTTP 状态和业务结果；requestId 使用本次值，响应头 `Idempotency-Replayed: true`。结果是原始快照，不是当前状态。
4. V1 不缓存失败结果：确定性业务拒绝与暂态失败均回滚业务及 Key；重试重新授权和校验，不承诺失败响应不变。技术死锁/锁超时只在回滚确定后允许有限重试，不能换 Key 自动重做未知提交。
5. COMMIT 返回不确定时，用同一 Key 在新连接查询：存在完成记录则重放；原事务仍进行则处理中；无法确认时 `503 IDEMPOTENCY_RESULT_UNKNOWN`，客户端保留同一 Key 重试。只有确认原事务回滚且唯一键可获得时才重新执行；不得把连接断开等同回滚。

## 保留与清理

V1 技术默认：从成功提交起至少保留 7×24 小时，expires_at 按最终提交阶段的数据库时间计算，事务耗时不得缩短窗口。该默认是公开 API 契约，不是新的已确认业务 BR；部署若需延长，更新契约，不得缩短已承诺窗口。

expires_at 到期视为失去重放保证；记录仍存在时可继续安全重放/识别冲突，后台分批清理已完成且过期记录，不删除活动事务。清理后服务器可能视为新请求，因此无法保证返回“Key 已过期”，也不保证跨清理点行为一致。客户端不得主动复用旧 UUID，超过窗口的未知结果先查询/人工核对，禁止自动重做。业务唯一约束与状态机必须独立成立，尤其收款登记/退款等财务唯一规则在 DC-003 确定前不得据 7 天幂等承诺长期去重。

response_body 只保存最小可重放结果（ID、状态、版本、金额摘要），不保存 Token、银行凭证或联系人全文；UTF-8 JSON 最大 64 KiB，超限在提交前拒绝并回滚，不截断成功结果。清理不连带删除业务事实或审计。

## 验收

- 同主体同 Key 的相同并发请求最多一次副作用；同 Key 跨 approve/reject 或跨目标返回 409。
- 不同用户复用 Key 仍各自执行业务授权、唯一约束和状态检查。
- 业务已提交但响应丢失、COMMIT 连接中断时可用原 Key 恢复，不重复业务写入。
- 回放前撤销权限或移交客户，不能读取旧结果；有效重放不被旧 expectedVersion 阻断。
- 失败无残留 PROCESSING；唯一键等待超时、事务回滚、7 天边界及清理后行为有真实 MySQL 测试。
